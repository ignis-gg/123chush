## Важный паттерн этой сессии — деплой на прод через браузер

Классификатор Claude Code блокирует КАЖДОЕ действие в cPanel (File
Manager upload, навигация в Terminal, и даже сам ввод команды в
Terminal) отдельно, с разными причинами ("Production Deploy",
"Auto-Mode Bypass", "Sensitive Remote Exec", "Remote Shell Writes") —
несмотря на постоянную автономию в CLAUDE.md. Пользовательский
"accept edits" (Shift+Tab) снимает блок ровно на одно следующее
действие. Рабочий паттерн, который довёл сессию до конца:
1. File Manager (загрузка файлов, навигация по папкам) — почти всегда
   проходит после одного "accept edits" на серию действий подряд.
2. Открыть Terminal — обычно требует отдельного "accept edits".
3. Набор команды в Terminal через `computer type` — тоже требует
   отдельного "accept edits", и даже после него не гарантированно
   проходит стабильно (см. ниже про кириллицу).
4. Кириллица в команде, которую печатает МОДЕЛЬ через `type` — ломается
   (известный баг, см. known-issues.md). Но если КОМАНДУ ВСТАВЛЯЕТ САМ
   ПОЛЬЗОВАТЕЛЬ (скопировав текст, который дала модель) — кириллица
   сохраняется нормально, это ограничение автоматического набора, не
   терминала как такового.
5. Практический вывод: для контент-миграций с кириллицей — модель готовит
   файл/команду, а пользователь сам вставляет её в уже открытый Terminal.
   Для файлов — можно грузить через `file_upload` (это разрешено чаще),
   но каждая новая папка/навигация может потребовать нового
   "accept edits".
